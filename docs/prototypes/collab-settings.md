# 可视化设置页 + 工作台运行台 · 交互原型 v1

> 对应票：#6《做出可视化设置页与工作台状态面板的交互原型》
> 原型文件：`docs/prototypes/collab-settings.html`（单文件、零依赖，双击即开）
> 性质：便宜、粗糙、供吐槽。按钮基本不落地，**没有任何 fetch、没有任何假后端调用**。
>
> **v1 改了什么**（相对 v0）：`#5` 已关闭，画面上原本 6 处「待 #5」灰虚线占位**全部填实**；
> 6 处假文件名（`task.md / plan-r1.md / checklist-r1.md / verdict-r1.md / plan-r2.md`）按 #5 A1 换成真名；
> 新增置顶常驻状态条（窄屏滚动时不丢当前任务）；角色行改成 `<details>` 折叠（460px 装不下三行完整绑定）；
> 新增 F 卡「已定 / 仍待定」把每一处已定指回票据。

## 0. 一句话主张：承载位置 = 右侧看板里的「设置与运行台」分页

不是独立设置页，不是控制条齿轮弹层，而是**现有右侧抽屉里加第二个分页**（「任务看板」/「设置与运行台」并列）。配置与现状分上下两段，**同一页滚动**，中间用一条 `以上为配置 · 以下为现状` 的横线切开。

选它的三个理由，全部来自 #2 查到的挂载点约束：

1. **运行台必须拿到 sessionId，而设置面板拿不到。** #2 结论：`settings.section`、`settings.plugins.tab`、`plugins.item`、`main` 四个全局挂载点的 standardProps 里**没有 sessionId**（`slot-catalog.ts:2669 / :3805`）。而这一页的核心价值是「当前任务卡在 6 目录的哪一格、谁在等谁」——这是会话内状态。放进独立设置页，就只能退化成「展示全局配置 + 一句『请在会话内查看看板』」，等于把最重要的一半砍掉。
2. **「独立路由」这一项根本不存在。** 客户端没有 hash / pushState（#2 grep 0 命中），桌面端 `setWindowOpenHandler` 一律 deny，不能承诺 URL 直达、也不能开独立窗口。所谓「独立设置页」只能做成 `main` + `sidebar.panellist` 的整页——还是应用内、还是拿不到 sessionId，却要用户离开当前任务才能改配置。
3. **齿轮弹层装不下。** 控制条按钮高 26px（`client.js:49`），弹层里要塞 3 行角色绑定（每行 3 个字段）+ 6 个配置项 + 一个运行台，弹层必然长成一个抽屉——那不如一开始就做成抽屉。

反面代价我也承认：**配置写 `state.json` 是机器级共享（`dsh-client-ui-settings/README.md:112`），塞进会话抽屉后，用户在 A 会话里改的东西会改到 B 会话身上**。这是本方案唯一的粒度裂缝。原型的处理是老实写在页头上（`写入 state.json`），不假装它是会话级。如果用户不能接受这条裂缝，唯一干净的替代是「配置进 `settings.section`、运行台留在看板」，代价是两处割裂——这正是本原型要主张放弃的方案。

### D · 角色最近动作（现状）

四行：Planner / Executor / Reviewer / 人类。每行 = 角色名 + 最近一次动作摘要 + 相对时间戳。数据来源标注为「按 Workspace mtime」——因为 #4 Q2 已把 `records.json` 降级为派生缓存，看板改读 Workspace。

v1 修掉一处自相矛盾：Executor 行原本写「交付 `03-任务清单/impl-r1.md`」，与 #5 A4「六目录里不设执行记录」直接冲突，改成「改了仓库 4 个文件（六目录零写入）」。

这一块是「谁在等谁」的另一半：黄框说的是**流程在等什么**，这一块说的是**每个人最后动了什么、多久没动了**。

## 2. 刻意没做的部分

| 没做 | 为什么 |
|---|---|
| **向导式分步表单**（3 步 next/prev） | 三行角色绑定之间有耦合（载体 × 权限档 × 审核档位要一起看），向导强制线性顺序，反而让人来回翻。用户实际动作是「一次核对 3 行」，不是「走完 3 步」。 |
| **独立页面 / 独立窗口 / URL 直达** | 客户端无路由、`window.open` 一律 deny（#2），做出来就是假的。 |
| **控制条齿轮弹层形态** | 26px 按钮开出来的弹层装不下这块信息量；即使做出来也只是个小抽屉。原型不浪费篇幅画它。 |
| **「删除当前工作台」按钮** | 删除时机 = Host 进程退出（#4 Q4）。给按钮等于给一个会让人误解的假能力。 |
| **broker 在线状态 / records 流水** | 纯进程内三角色时 broker 不该存在（#4 Q2）。在这一页画它，会暗示「没 broker 就跑不了」。 |
| **拖拽换后端 / 自由组合角色** | 不跨档位（#3 D1）。拖拽交互天然暗示任意组合，与约束相反，所以用下拉。 |
| **真数据 / 真接口** | 票面要求静态原型。所有按钮点了不落地；开关和分段控件只翻视觉态。 |
| **深浅色主题切换做成产品功能** | 页面左上角那条「原型工具条」是给评审用的，不属于设计。深色只是复用 `body[data-ds-dark-theme]` 变量验证配色在暗色下成立。 |
| **UI 里的文件编辑框** | 见 E 区理由：越权判定靠快照 diff，UI 写入会与角色越权混淆。改为「打开文件夹」把编辑交回操作系统。 |

## 5. 假数据的形状

不是随手编的：

- task id `t-2026-1125-01`、session `s-8ac2`、host `41216-9f3c1a` —— 对齐 `<pid>-<boot-id>/<session-id>/<task-id>` 四段层级（#4 Q3）。
- 清扫示例 `39812-3f9a1c（pid 已不存在）` / `40120-77b20e（boot-id 不匹配，是上一次开机的）` —— 就是 #4 触发清单 #4 的两条判据，一对一。
- 6 个目录名一字不差：`01-原始任务需求和目的` / `02-执行方案` / `03-任务清单` / `04-审核结果` / `05-修改方案` / `06-最终审核`。
- 6 个文件名一字不差（#5 A1）：`request.md` / `plan.md` / `tasks.md` / `review-r<N>.md` / `revision-r<N>.md` / `final.md`。
- 角色名用 `planner` / `executor` / `reviewer`（+ 中文注释），因为 #3 D4 已定名，不再用「主 agent / 规划 agent / 审核 agent」。
- 轮次数字自洽：`round=2 / rejection_count=1 / 上限 2` → 已写 `review-r1.md` 与 `revision-r1.md`，正在写的是 r1 的修改方案（不是 r2），第 2 轮复审将落 `review-r2.md`。

## 6. v0 自评的三条，v1 怎么处理

写在这里，省得评审时绕弯：

1. **460px 撑不住三行角色绑定** —— 采纳。改成每行 `<details>` 折叠：静息态一行摘要（角色名 + brief + 「展开」），点开才看到载体/模型/读写边界。窄屏 460px 下 A 卡从约 500px 压到 223px，三行一屏放得下。
2. **运行台信息密度过高** —— 部分采纳。没有重排（6 格 + 等待框 + 轮次 + 状态集 + 4 行动作 + 6 行文件确实要滑两屏），而是补了置顶常驻状态条：不管滚到哪，「哪个任务、什么状态、驳回几次、在等谁」始终在视野顶部。
